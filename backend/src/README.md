# Source Code (`src/`)

Основной исходный код приложения, организованный по принципам **Clean Architecture** и **Domain-Driven Design**.

## 📁 Структура

```
src/
├── api/                    # HTTP API слой
│   ├── routers/           # Роутеры FastAPI по доменам
│   │   ├── registrations/ # Роутеры регистрации команд
│   │   └── telegram/      # Роутеры Telegram настроек
│   └── webserver.py       # Конфигурация веб-сервера
├── domain/                # Доменная логика (DDD)
│   ├── models/           # Доменные модели данных
│   ├── services/         # Бизнес-логика доменов
│   └── repositories/     # Абстракции репозиториев
├── infrastructure/       # Инфраструктурный слой
│   ├── adapters/         # Адаптеры внешних сервисов
│   └── repositories/     # Конкретные реализации репозиториев
├── settings/             # Конфигурация приложения
└── entrypoints/          # Точки входа приложения
```

## 🎯 Архитектурные принципы

### Domain-Driven Design (DDD)

**Домены** - это основные бизнес-сущности системы:
- `registrations` - Регистрация команд на хакатон
- `telegram` - Интеграция с Telegram Bot API

### Clean Architecture

**Слои** организованы по уровням зависимости:
1. **Domain** - Бизнес-логика, независимая от внешних зависимостей
2. **Infrastructure** - Конкретные реализации внешних зависимостей
3. **API** - HTTP интерфейс для внешнего мира

### Dependency Injection

Используется **Bootstrap** паттерн для инициализации зависимостей:
- Сервисы создаются один раз при запуске
- Передаются через dependency injection в роутеры
- Позволяет легко тестировать и заменять реализации

## 📋 Компоненты

### API Layer (`api/`)

**Роутеры** определяют HTTP эндпоинты:
- `registrations/router.py` - CRUD операции с регистрациями
- `telegram/router.py` - Управление Telegram уведомлениями

**Особенности:**
- Валидация запросов через Pydantic модели
- Обработка ошибок с детальными сообщениями
- Автоматическая документация OpenAPI

### Domain Layer (`domain/`)

**Модели** (`models/`) - чистые бизнес-сущности:
- `TeamRegistration` - модель регистрации команды
- Автоматическое присвоение дат и валидация

**Сервисы** (`services/`) - бизнес-логика:
- `RegistrationService` - обработка регистрации команд
- `TelegramService` - интеграция с Telegram API

**Репозитории** (`repositories/`) - абстракции доступа к данным:
- Определяют интерфейсы для работы с данными
- Независимы от конкретных технологий хранения

### Infrastructure Layer (`infrastructure/`)

**Адаптеры** (`adapters/`) - интеграция с внешними сервисами:
- `sql_model_adapter.py` - подключение к PostgreSQL через SQLModel

**Репозитории** (`repositories/`) - конкретные реализации:
- `TeamRegistrationRepository` - работа с базой данных регистраций

### Settings (`settings/`)

**Конфигурация** приложения через TOML файлы:
- `settings.toml` - базовые настройки
- `settings.dev.toml` - настройки разработки
- `settings.staging.toml` - настройки staging среды

### Entrypoints (`entrypoints/`)

**Точки входа** приложения:
- `main.py` - основной файл запуска с FastAPI приложением

## 🔄 Поток данных

```
HTTP Request → Router → Service → Repository → Database
     ↑              ↓         ↓         ↓
  Response ← Validation ← Domain ← Infrastructure
```

1. **Запрос** приходит в роутер
2. **Валидация** данных через Pydantic модели
3. **Бизнес-логика** в доменных сервисах
4. **Доступ к данным** через репозитории
5. **Хранение** в базе данных через инфраструктуру

## 🧪 Тестирование

### Unit тесты
Тестируют отдельные компоненты в изоляции:
- Доменные сервисы
- Модели данных
- Репозитории

### Integration тесты
Тестируют взаимодействие компонентов:
- HTTP эндпоинты
- Интеграция с базой данных
- Внешние сервисы (Telegram)

## 🔧 Разработка

### Добавление нового домена

1. Создайте папку в `src/domain/`
2. Определите модели в `models/`
3. Реализуйте бизнес-логику в `services/`
4. Создайте абстракции репозиториев в `repositories/`
5. Добавьте роутеры в `api/routers/`

### Миграции базы данных

Используйте **dbmate** для управления схемой БД:
```bash
# Создание миграции
dbmate new feature_name

# Применение миграций
dbmate up
```
